# Audit/debug report

Repository: `vanphandinh/fucking-cool-ai-bot`

Baseline: `d2b87db50c51a811d3cc226e338008e9d83a6e66` (`main`).
Scope: every application module, existing tests, configuration and deployment
files; regression tests use fake Telegram/provider transports and local servers.

## Findings and fixes

| Finding | Evidence before the fix | Resolution |
|---|---|---|
| Tool quota reset across provider fallback | One question executed 12 calls despite the documented cap of 8; a one-round budget executed three rounds | Share both counters across the entire completion; reject tools in plain passes |
| Transient tool errors disabled tools permanently | Two questions sent tools flags `[True, False, False]`; malformed generation could quote an unsupported-tools phrase | Inspect structured error messages, prioritize generation errors, retry plain without disabling future tools |
| Compressed page memory amplification | HTTPX expanded a compressed chunk before the 2 MB limit; reviewer reproduced about 81 MB peak allocation for a 32 MiB expansion | Request identity encoding and reject compressed responses before decoding |
| Slow page/DNS could indefinitely hold the chat lock | A trickling body completed beyond the requested total timeout | Overall reader deadline covers DNS, redirects and Jina/direct fallback |
| Chat queue could accumulate indefinitely | Waiting on a busy chat lock had no expiry | `QUESTION_TIMEOUT_SEC=180` bounds waiting, processing and answer delivery |
| Quadratic HTML cleanup blocked every chat | Alternating retained/removed siblings took about 1.5 s at 200 KB and 6 s at 400 KB, bypassing asyncio timeouts | Incremental text extraction, capped output/token buffer, event-loop checkpoints; no DOM mutation |
| Restart discarded pending Telegram messages | `delete_webhook(drop_pending_updates=True)` ran on every start | Preserve pending updates |
| Startup/shutdown resource cleanup gaps | Unexpected `get_me` failure left clients unclosed; update handlers could outlive provider clients | Common cleanup scope, one signal owner, cancel/join active handlers before closing clients |
| Public-address checks accepted multicast and translation ranges | Literal validation accepted multicast and NAT64-embedded loopback | Shared predicate rejects unsupported destinations at URL, DNS and connection boundaries |

Multicast/NAT64 findings are defense hardening: a successful TCP exploit in the
default Docker deployment was **not** demonstrated. NAT64 reachability depends
on the network's translator configuration.

## Audit loop and validation

1. Read application/deployment code and Git history. No existing Actions runs or
   open PRs were found at the initial inspection.
2. Baseline: **194 passed, 0 failed**; Ruff and installed dependency compatibility
   checks passed.
3. Added failing regressions, fixed root causes, and reran original tests.
4. Independent review found two additional cases: quoted generation errors and
   quadratic HTML cleanup. Reproduced and repaired both, then fixed a text-word
   boundary regression introduced by incremental parsing.
5. Final local validation: **194 legacy checks plus 15 unittest regressions pass**;
   Ruff, bytecode compilation and `pip check` pass on Python 3.12.

Reproduce locally after installing `requirements.txt`:

```bash
python tests/run_tests.py
python -m unittest discover -s tests -p 'test_*.py' -v
python -m ruff check .
python -m compileall -q app tests
python -m pip check
python -m pip_audit --progress-spinner off
```

The test executor had inherited SOCKS proxy variables without HTTPX's optional
SOCKS dependency. Those variables were removed **only for offline test commands**
so their loopback fake servers could run. No production configuration was changed
to work around that environment issue.

The first dependency advisory scan found no vulnerable application packages but
flagged the environment's old pip 25.0.1. Docker/CI now upgrade pip to at least
26.2 before installing packages. Advisory results describe the resolved packages
at audit time; dependency ranges are not a reproducible lockfile.

## Continuing checks

`.github/workflows/audit.yml` runs lint, both suites, dependency compatibility,
advisory scanning and the production image build on push/PR. Python 3.11 and 3.12
are covered by the CI matrix. Actions are pinned to reviewed release commit SHAs
and workflow permissions are read-only. This is a verification gate, not an
unattended agent that rewrites or merges future code.

## Remaining limits

- No live Telegram, Gemini, Groq, OpenRouter, Tavily or production SearXNG calls
  were made, and no production credentials/VPS were available for smoke testing.
- Docker is unavailable in the local executor; its build is delegated to CI.
- Compression-only pages are deliberately refused. IPv6 transition/tunnel
  addresses and unusually long HTML tokens are unsupported by the reader.
- Memory is still in RAM, scoped to the group (including its topics). Shutdown
  cancels in-flight answers; preserving pending updates does not provide durable
  replay of updates already acknowledged by Telegram polling.
- DNS resolution and DDGS use worker threads: cancelling the await frees chat
  handling, but cannot forcibly terminate a running OS/library call.
- Passing tests and review establish no remaining **confirmed** serious defect
  in the exercised scope; they do not prove the application is bug-free or
  validate third-party service behavior in production.
